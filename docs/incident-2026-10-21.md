# 上传完成后执行连接中断

## 结论

失败发生在官方 CLI 的工作目录前置命令阶段，H3 生成脚本没有被发送。此前根据界面停留在“传送素材”推断上传失败是不准确的。

固定依赖 `google-colab-cli 0.7.4` 使用 `jupyter-kernel-client 0.9.0`。后者在 WebSocket 的初始 10 秒等待返回 False 后仍继续发送命令，接着因 `connection_ready` 尚未设置而抛出 `Connection was lost`。CLI 的前置命令位于清理用的 `try/finally` 之外，异常后监听线程继续存活，令子进程不能及时结束。

时区：Asia/Shanghai，2026-10-21。依据本机官方 CLI 历史和传输日志；不附原始日志、账号、素材或请求内容。

这期间没有第二条 `execute_request`，没有 H3 任务提交记录，也没有生成结果文件。失败请求设置为 1088×1920、5 秒、20 步，但没有进入生成，因此不能用这次失败判断 1080p 是否会显存不足。握手为什么变慢没有足够证据，未归因于用户代理或浏览器设置。

## 复现与修复

`tests/test_colab_transport.py` 在真实依赖的 ColabRuntime / KernelClient / WebSocket 路径上注入延迟就绪，隔离网络与云端算力。修复前，前置命令确定性抛出 `Connection was lost`；修复后，前置命令与任务命令各发送一次并正确收取回复。连接永不就绪、静默执行超时和前置命令失败清理用例也先失败再通过。

v0.1.1 在本工作台 CLI 子进程内加兼容层，不修改全局安装：

- 初次等待后仍未连接时再等最多 20 秒；确认 ready 后才发命令，失败则关闭连接。
- 前置命令的异常也关闭监听线程；IOPub 和 shell 等待严格受同一个执行时限约束。
- 不自动重发执行命令，不因连接不确定而重复消耗生成额度。
- 显示“素材已上传，正在连接生成执行器”和“工作流已送达，正在提交生成”，避免将后续故障误报为上传失败。
- 分别保存操作故障；传输事件日志只保留必要事件及脱敏警告，禁用官方 CLI 的全局请求头/代码 DEBUG 转储。

已有的有限传输保护窗口、远程空闲及总时限、释放核对继续生效。界面正常重启保存队列历史；升级仍须等待队列为空并确认运行时已释放。

## 验证边界

真实云端连接检查使用普通 CPU 和合成文本，不申请 GPU、不下载模型、不生成视频。GPU 推理成功的既有证据属于 v0.1.0。此次修复的目标是执行连接与清理；1080p 推理能力和长期网络稳定性没有新增验收结论。
